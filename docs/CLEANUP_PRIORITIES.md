## 最大风险来源

1. `archived/FAD_RNAErnie/` 同时存在大型ZIP、解压checkpoint和多折模型，单个模型约333 MiB。
2. `docs/v1/仿真计算数据/` 中混入NUPACK源码、构建目录、近500 MiB折叠JSON和原始仿真材料。
3. `artifacts/` 中大量结果没有统一的实验ID、配置与完成标记。
4. canonical train/val/test 在历史 BestModel 文档中存在完全相同的副本。
5. 当前 Git 有29,111条状态记录，不能通过reset或批量删除“快速清理”。

## 推荐执行批次

### Batch A：主线冻结

- 将clean mainline放到独立分支或独立仓库。
- 回收v8与v11–v13服务器最终CSV。
- 跑通30/100-seed正式复核并生成完整运行包。

### Batch B：文档与第三方资源分离

- 当前有效文档提升到 `docs/current/`。
- PDF进入 `docs/references/`，保留引用索引。
- NUPACK源码和构建目录进入外部 `vendor/` 存储，不进主线Git。
- 原始仿真材料进入只读数据存储并登记SHA256。

### Batch C：历史模型归档

- RNAErnie、RNA-FM、CNN、ESO按“代码、最终指标、必要权重”制作归档包。
- 比对压缩包与解压副本的哈希后，只保留一种形式。
- 不再把历史模型放入主线Python导入路径。

### Batch D：结果产物治理

- 仅保留有配置、数据哈希、指标和状态的运行。
- 临时checkpoint、重复预测和失败中间文件转冷存储。
- 生成最终实验注册表后，再讨论删除列表。

## 删除门槛

任何旧文件只有在同时满足以下条件后才能删除：

1. 已有SHA256；
2. 已确认不是唯一原始数据；
3. 已确认不被正式脚本和文档引用；
4. 已存在另一份可读取副本或明确判定为可再生缓存；
5. 删除清单经过人工确认。
