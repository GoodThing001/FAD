## 1. 一句话总览

本阶段按实施方案完成了三件事：**① 把「变异 → 打分 → 选样 → 待测 → 回填 → 重训」整条候选闭环工程化并冻结接口（v0.2.0），修掉台账索引错位、回填校验缺失、恢复无指纹核对三个 P0 与四个 P1/P2；② 导出 96 条（1 板）真实待测批次并在 `PARKED` 停机，等生工侧真实 GBSA；③ 用预注册的 100-seed 确认运行定案选样策略**——`greedy`（按预测最低取 50 条）通过主判据，但其收益性质必须说清：**它不靠"多数种子赢"（胜率恰 50/100、中位差≈0），而靠避免灾难性批次 + 稳定命中池内真实强候选区（top-10% 召回 +0.215，99/100 seed 更优）**。全程不新增任何 MD/MM-GBSA 计算，训练目标、采集分数、排序与成功判据只用独立 `gbsa`；历史加权 `label=0.961·Gap2+0.039·gbsa` 未验证，不进入任何环节。

## 3. 闭环接口与状态机（v0.2.0）

```
变异生成候选池 → 代理打分 → 选样(策略+预算) → 批次导出 → 表内标签(回顾式) → 立即重训 → 下一轮
  mutate.py      predict    selection.py   round_NNN_batch.csv
                                            ↘ 真实测量(前瞻式) → PARKED → --ingest 回填 → 重训 → 下一轮
```

状态：`init → selected → awaiting_labels → labels_ingested → retrained`。**停机判据**：还有候选未回填 → `PARKED` + 退出码 3；候选池耗尽 → `pool_exhausted`；空批次 → `empty_batch`——三者都不会写 `DONE`。运行器支持 `acceptance.expect_marker/expect_exit_code`，把"该 PARK 的运行绝不许 DONE"变成硬断言。

每个检查点目录的产物（`runs/<run_id>/checkpoints/`）：

| 文件 | 作用 |
|---|---|
| `ledger.csv` | 候选台账（每候选一行，含 `candidate_id`(sha256[:16])、父序列溯源、`selection_policy/role/position`、`model_id/feature_version`、`pred_gbsa/sigma_gbsa`、`ood_flag/ood_hamming_threshold`、`protocol_id`、`status`、`measured_gbsa`）。行一经导出即追加不删除；回填吸收与协议钉定时会**更新对应行的状态字段**（`status/measured_gbsa/protocol_id`），每次改动都有审计记录（`protocol_changes.jsonl`/回填报告），预测类字段不被改写 |
| `round_NNN_batch.csv` | 交给外部测量的批次（含 `pred_gbsa/ood_flag/protocol_id`），即回填模板 |
| `round_NNN_batch_manifest.json` | 交接清单：导出列、模型/协议/目标/接口版本 + 运行指纹 |
| `round_NNN_ood_strata.csv` | 按突变数分层的 OOD/距离/误差报告 |
| `metrics.csv` | 每轮一行：`n_labeled_before/n_new_unique/n_labeled_after/model_n_train/n_awaiting/…/ood_fraction/batch_ood_fraction/ood_threshold_hamming/holdout_spearman_pre/post` |
| `state.json` + `fingerprint.json` | 完整状态；检查点指纹（配置/数据/池/留出哈希 + 源码哈希） |
| `pending_batches/batches/batch_<id>/` | ParkOracle 台账：`batch.csv`、`labels.csv`(pass)、`failures.csv`(QC fail，持久化)、`batch_manifest.json` |

**关键语义**：`model_n_train` = 采集**前**已标注数；`n_new_unique` 只计真正新增的唯一标签；台账每一行的预测按 `selection_position`（可选池内位置）与序列逐行对齐。

## 4. 三个 P0 缺陷的修复（本次核查发现，均已修复并有测试）

| 问题 | 修复 | 验收 |
|---|---|---|
| **台账索引错位**：原代码把 `mu_all.mu[k]` 写到批次第 k 条，而 `selection["indices"]` 是可选池索引 → 每行的 `pred_gbsa` 属于另一条序列 | 全部预测/OOD/角色字段改按 `sel_pos` 对齐，台账新增 `selection_position` | `LedgerAlignmentTest`：用第 1 轮训练集重拟合同一代理，逐行比对预测（1e-9 容差），并断言选中确实非前缀。**修复前批次（含 30-seed v1）的 `pred_gbsa/best_pred_in_batch` 作废**；发现指标出自状态标签、不受影响 |
| **回填校验不完整**：只验序列在批次内；不核 `candidate_id`、不核协议、`fail` 只进内存重启即丢 | `ingest` 先全量校验再原子写入：`candidate_id` 重算比对、`protocol_id` 非空且过白名单、状态仅 `pass/fail`、同文件/跨文件冲突拒收且不污染已确认值；`pass/fail` 各自写入 `labels.csv/failures.csv`（临时文件 + `os.replace`） | 6 个用例：错误 ID/缺失/未批准协议拒收、QC fail 跨重启持久化、重复提交幂等、批次闭合后清 `open_batch` 与陈旧 `PARKED`、fail 候选永不再入池 |
| **恢复无指纹核对**：`--resume` 不核对原配置/数据/候选池，运行器无统一恢复入口 | 检查点写 `fingerprint.json`（配置/数据 SHA256/池/留出/初始集哈希/源码哈希）；恢复时对 config/data/pool/holdout **强制匹配**（不符即报错），源码变动告警但保留原始指纹；新增 `run_experiment.py --resume-run <run_id> [--ingest csv]`（复用原 config、`resume_history.json`、先删旧标记再跑） | `FingerprintResumeTest`（变配置拒绝、无指纹拒绝）+ 端到端用例：PARKED → 全批回填 → `DONE`、旧 `PARKED` 被清除 |

**同步修复的 P1/P2**：① 前瞻式生成对完整 2000 条标准表 + 初始集 + holdout 全量排重（出口再排历史批次），计数入指纹；② OOD 改为**采集前**计算并保存当轮阈值与分层计数（修复"加入本轮标签后才算 OOD"的偏乐观）；③ 运行器缺 registry 条目即失败（不再显示 `registry_match=true`）；④ 比较驱动缺任一 seed/策略/轮次即非零退出（`completeness.json`）；⑤ `surrogates.py` 文件头升 v0.2.0。

## 5. 候选生成与 96 条真实待测批次（已 PARKED）

**关键事实**：2000 条测量库相对 WT 的突变数是 **4–13 的壳**（均值 9.87，直方图 `{0:1,4:2,5:9,6:34,7:80,8:247,9:410,10:481,11:444,12:226,13:66}`），而不是以 WT 为中心的球。生成 **1–3** 个突变的候选超出已测突变数范围，**4–5** 极稀疏（各 2/9 条）；闭环现默认取已标注集合的突变范围（`--min-mutations/--max-mutations` 可覆盖）。

**交接批次**（服务器 `runs/srv_handoff_20260930_182400`，配置 `configs/experiments/loop_handoff_96.json`）：

| 项 | 值 |
|---|---|
| 规模 | **96 条候选（1 板）**，seed 101（在开发集 1–30 之外），greedy |
| 候选分布 | `n_from_wt` 5–13；与完整标准表排重（excluded=2000）、与 init/holdout 排重 |
| 导出列 | `batch_id, candidate_id, sequence, pred_gbsa, ood_flag, protocol_id` |
| 指纹 | `batch_manifest.json` + `fingerprint.json`（模型 `xgb_boot10_xgboost`、`seq303_screen100`、数据 SHA256、源码哈希） |
| OOD | 批次 OOD 比例 0.0；分层报告随批次给出 |
| 状态 | **`PARKED`（rc 3）**，`batch_id=46844fc08eb8`，96 条全部待回填 |

**回填前的硬性要求**：批次协议串目前是占位符 `gbsa_pending_protocol`。**该批次不能按现稿命令直接受控回填**：批准列表为空会接受任意非空协议串，而临时在命令行加 `--approved-protocols` 会被恢复指纹拒绝。正式做法（2026-10-01 复核后已实现并再次补强）：与生工团队确认统一 QC 协议串后，走**有审计记录的协议钉定流程**——`python scripts/run_experiment.py --resume-run srv_handoff_20260930_182400 --pin-protocol <协议串>`（写入 `checkpoints/protocol_changes.jsonl`，同步重写 config/指纹/台账/批次 CSV 与**两份清单**：检查点 `round_NNN_batch_manifest.json` 与 Oracle 副本 `pending_batches/batches/batch_<id>/batch_manifest.json`，含各自内嵌指纹；钉定仅限仍 `PARKED` 且尚无任何回填的运行、协议串不得为空），再 `--resume-run … --ingest labels.csv` 回填；**不要手工改旧运行的配置文件**。回填后：QC `fail` 持久化并永久排除该候选；全批 pass/fail 闭合后自动**重训**并把状态推进到 `retrained`、台账行更新为 `labeled/failed`（含 `measured_gbsa`），运行器仅在 `state.status=retrained` 时写 `DONE`（关闭评估也只跳过 holdout 打分、不跳过重训）——这条路径已有端到端验收测试（全批 pass、混合 pass-fail、钉定三连、无评估重训、已回填禁钉）。

## 6. 选样策略：30-seed 开发比较（回顾式代理表）

协议：每 seed 划分 300 初始 + 200 holdout + 600 候选池，5 轮 × 50 条预算，四策略同 seed 共用划分/池/预算；主指标 `best_selected`（该策略**自己查询过**的候选里最低的真实 gbsa），`regret = best_selected − pool_best`。

| 策略 | 末轮 regret 均值 | 相对 random 配对 Δregret（95% CI） | Δ<0 的 seeds | holdout Spearman 差 |
|---|---:|---:|---:|---:|
| random | 2.130 | — | — | — |
| **greedy** | **0.451** | **−1.679 [−2.637, −0.785]** | 15/30 | +0.031 [+0.016, +0.046] |
| greedy_diverse | 1.043 | −1.087 [−1.965, −0.302] | 13/30 | +0.024 [+0.005, +0.044] |
| maxmin_coverage | 1.880 | −0.251 [−1.402, +0.868] | 11/30 | +0.016 [−0.003, +0.034] |

**30-seed 的如实读法**：greedy 平均优势确定，但仅在 15/30 个 seed 严格胜出，配对中位数 −0.083、Q25/Q75 = −3.51/0——均值优势由尾部驱动。v1 包因台账索引 bug 其预测列作废；§7 修复后的 **v2 重跑**（`srv_strategy_compare_30seed_v2_20260930_182900`，`completeness.json` 通过）发现指标与 v1 **逐位一致**，证明修复只影响台账记录、不影响选样路径。

## 7. 100-seed 预注册确认（发布候选定案）

口径与判据在运行**之前**写死（[预注册文档](../../项目记录/发布候选预注册_100seed_20260930.md)）：seeds 1001–1100（与开发集不重叠），其余冻结项与 30-seed 相同；主判据 = 第 5 轮配对平均 regret 的 bootstrap 95% CI 上界 <0；同时必须报告中位数/Q25-Q75/胜率/最差 10% seed；附加指标（top-5 中位数、top-10% 池召回）与分层压力检验的算法先于运行实现并测试。

运行 `srv_strategy_compare_100seed_20260930_201309`：`DONE`，`completeness.json` ok=true（400 子运行 = 100 seeds × 4 策略，2000 行），数据哈希与 registry 匹配，后端如实记录 `xgb_boot5_xgboost`。

| 指标（greedy vs random，第 5 轮配对） | 值 | 判读 |
|---|---|---|
| **Δregret 均值（主判据）** | **−1.8781 [−2.5189, −1.2614]** | CI 上界 <0，**判据达成** |
| 中位数 / Q25 / Q75 | −0.0173 / −3.4516 / 0.0000 | 中位差≈0 |
| **胜 / 平 / 负** | **50 / 37 / 13** | 不是多数种子严格领先 |
| 最差 10% seed（相对 random 表现**最差**的 10 个，均值） | **+1.7627**（seeds 1062, 1069, 1055, 1056, 1078, 1085, 1081, 1095, 1065, 1072） | 少数种子上 greedy 更差，被大幅改善的种子抵消 |
| 改善最大的 10 个 seed（均值） | −8.4125（占平均差 −1.878 的 ≈44.8%） | 平均优势由少数大幅改善的 seed 驱动 |
| Δtop-10% 池召回 | **+0.2153 [0.1983, 0.2323]，99/100 胜** | 最强信号：预算稳定放进真强候选区 |
| Δtop-5 中位数 | −0.9424 [−1.2144, −0.6833]，70/100 胜 | 查询到的强候选质量一致更好 |
| Δholdout Spearman（末轮重训后） | −0.0043 [−0.0150, +0.0066]，46/100 | **30-seed 的 +0.031 未复现**，如实记录 |

> **勘误（2026-10-01 复核）**：本表初版把"最差 10% seed"标反为 −8.4125（实为**改善最大**的 10 个）。已用固定代码从 `runs.csv` 重新计算并回填上表：最差 10% = +1.7627、改善最大 10 个 = −8.4125（占总均值差的 ≈44.8%）、分布 50 胜/37 平/13 负；主判据与其余指标不受影响（逐位一致）。派生汇总（`summary.json`/`completeness.json`/`metrics_recomputed.csv`）已就地重算，`runs.csv` 与服务器运行目录未改动。

次要策略（探索）：`greedy_diverse` Δregret −0.92 [−1.65, −0.19]（45 胜/24 平/31 负）；`maxmin_coverage` −0.89 [−1.58, −0.22]（42 胜/26 平/32 负）；两者 top-5 改善不显著。

**分层压力检验**（`ood_strata_aggregate.csv`，11 层 × 4 策略；**口径已收窄**）：以下 MAE 只来自**被选中且揭示标签**的候选，不能推断整个候选池各层误差平坦；"层内最优"指**预测值**最优，不是真实 GBSA 命中证据。在此口径下：已揭示候选的预测误差在各层无强烈分层（7–9）；OOD 集中在稀疏层（n=0/4 为 0.60–1.00，n≥5 ≈0–0.07）；greedy 选中的候选更靠近训练集（最小 Hamming ≈4.3–4.9，覆盖类策略 ≈5.1–5.4），且在稠密层（7–12）几乎总选中层内**预测**最优（0.82–1.00）。

**定案**：**默认选样策略冻结为 `greedy`**。定位明确为——按预测最低取 B 条 = 稳定把预算放进池内真实强候选所在区域（召回 99/100 更优）；**不是**"多数种子严格领先"（50 胜/37 平/13 负、中位差≈0），其平均优势由少数大幅改善的种子驱动、并抵消少数种子上的劣势。holdout Spearman 无差异说明当前收益来自**选样利用**而非**代理被采集改善**。
