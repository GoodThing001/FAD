# Phase A 对接材料：GBSA 标签噪声上限测量（供生工团队）

> 2026-09-26。目的：用最小 MD 成本一步测出 gbsa 标签的噪声天花板，决定「副本平均
> 去噪」是否值得投入。全部依据见 `docs/论文改进/执行方案_MIX复测与MD去噪_20260924.md`。

## 1. 需要的数据

对 `runs/phaseA_diagnostic_subset_100.csv` 中的 **100 条序列**（已按 gbsa 十分位分层
选出，覆盖 min/median/max 与 25 个 >50 kcal/mol 离群区），每条跑：

- **5–10 条独立的 4 ns 短轨迹**（文献：Crean et al. JCIM 2022:577——5–10×4ns 足以
  可靠排序变体；快速预检可用 5–50 条 × 20–200 ps，Genheden & Ryde JCC 2010:837）；
- 每条轨迹**独立**算 MM-GBSA（沿用现有 Rosetta r_psp_MMGBSA 管线，与 2000 条主标签
  同源；平衡 ≥100 ps，帧间隔 > 自相关时间 ~5 ps）；
- 输出逐帧表：`Sequence, replica_id, frame_id, gbsa_raw, energy_components,
  protocol_version, batch_id, qc_status, failure_reason`。

## 2. 需要生工团队回答的三个数字

1. **每轨迹 GPU 时/成本**（100 条 × 5–10 副本的总成本由此估算）；
2. **旧 2000 条轨迹能否续跑补副本**（能续跑则增量成本大幅下降）；
3. **现有 MM-GBSA 协议参数**（igb、盐浓度、帧数、聚合方式）——用于协议矩阵（Phase B）
   的基线对照。

## 3. 回来后我们怎么算（协议已就绪）

```bash
# 副本-副本 Spearman = 噪声上限
python scripts/reproduction/label_audit.py --replica-file replica_gbsa.csv

# 用天花板公式决定投入规模：
#   ρ(r) = 0.412 / sqrt(ρ_rr + (1-ρ_rr)/r)
#   ρ_rr=0.65 → 5 副本 0.486、10 副本 0.498
#   ρ_rr=0.50 → 5 副本 0.480、r→∞ 0.583
```

判定规则：ρ_rr ≥ 0.5 且 ρ(5)−0.412 ≥ 0.05 → 进入分批去噪（Phase C）；
ρ_rr < 0.5 → 排查协议（最小化收敛/GB 奇点）或转向金标准子集（Phase D，FEP/ΔΔG）。
