# 候选闭环框架：已冻结接口 + 可跑通的下游流程（2026-09-30）

本文回答一个问题：**在代理模型本身还在迭代的前提下，怎样把“序列变异 → 选样 → 批次 → 标签回填 → 重训”这条下游链路先固定下来并跑通。**
配套的权威规格与验收清单见 [GBSA 代理接口与候选闭环实施方案](../项目记录/GBSA代理接口与候选闭环实施方案_20260930.md)（下称“实施方案”）。

---

## 1. 本轮固定了什么

| 事项 | 决定 | 理由 |
|---|---|---|
| 预测目标 | **独立 `gbsa`**（MM-GBSA，项目约定越小越强） | 项目当前唯一有 2000 条真实标注的量；不需要新算 MD |
| 加权标签 | **不使用** `label = 0.961·Gap2 + 0.039·gbsa` | 该权重尚未在本数据上得到有效验证，不能作为训练目标、采集分数、候选排序分数或成功指标 |
| 代理↔下游接口 | `INTERFACE_VERSION = 0.2.0`，冻结 `fit/predict`、`Prediction`、`TargetSpec` | 代理可以换实现，下游不必改 |
| 不确定度 | `sigma` **可选**；不提供时 `random/greedy/greedy_diverse/maxmin_coverage` 可运行；`mixed_control` 仅在 uncertainty 配额为零时可运行；`uncertainty_mixed` 拒绝 | 现有代理器没有经校准的 σ，不能让整条链路依赖它 |
| 候选空间 | 141 nt 适配体，13 个可变位点 `(30,31,32,33,89,90,91,92,127,128,129,130,131)`，每个位点 3 种替换；其余位置必须与 WT 相同 | 与数据生成约束一致；越界序列一律拒绝 |
| 待测批次 | 导出批次后进程以 `PARKED`（退出码 3）结束，**绝不写 `DONE`** | 没有真实标签时，禁止把“等待测量”伪装成完成的闭环 |
| 运行入口 | 一切实验走 `scripts/run_experiment.py <config>`，产出 config/数据哈希/环境/metrics/stdout/标记 | 可溯源、可复现 |

## 2. 接口契约（下游可以依赖的部分）

```python
# scripts/loop/interface.py
INTERFACE_VERSION = "0.2.0"
MUT_POS = (30, 31, 32, 33, 89, 90, 91, 92, 127, 128, 129, 130, 131)

@dataclass(frozen=True)
class TargetSpec:
    name: str = "gbsa"            # 预测/优化目标
    direction: str = "minimize"   # 越小越强
    report_column: str = "pred_gbsa"
    label_policy: str = "gbsa_only"

@dataclass(frozen=True)
class Prediction:
    mu: np.ndarray                 # 必填，必须有限
    sigma: np.ndarray | None = None  # 可选；给了就必须有限且 >= 0
    uncertainty_kind: str | None = None  # 给了 sigma 就必须声明种类
    feature_version: str = "seq303"
    model_id: str = "unknown"
```

代理实现只需满足：

```python
class MySurrogate:
    model_id = "..."           # 会写进台账
    feature_version = "..."
    def fit(self, sequences: list[str], y: np.ndarray) -> None: ...
    def predict(self, sequences: list[str]) -> Prediction: ...
```

**契约要点**：非有限 `mu/σ` 一律 `ValueError`；当前实现允许 `σ=0`，但不能把它解释为已校准的零误差；`sigma` 与 `uncertainty_kind` 必须成对；固定骨架检查在 `validate_sequences(..., check_scaffold=True)` 内完成。台账会记录 `model_id/feature_version/pred_gbsa/sigma_gbsa`，但当前 `loop.py` 写预测值时存在选中索引错位，修复前不能据台账预测列评估候选排序，详见实施方案 §7。

内置代理（`scripts/loop/surrogates.py`）：

- `xgb` → `XGBEnsembleSurrogate`（默认 10 个自举成员，`model_id=xgb_boot{n}_{backend}`），当前是接口可用的默认实现；30-seed 策略比较用了 5 成员 XGBoost，但其精度尚未按独立模型选择协议做 100-seed 确认；
- `fusion` → `ReleaseFusionSurrogate`，是发布版五模型均值适配器，`model_id=release_five_model_mean_v1`，**明确不是** v8 秩融合（0.375 那套指标不能挂到它名下）。

## 3. 下游流程与状态机

```
变异生成候选池 ──▶ 代理打分 ──▶ 选样(策略+预算) ──▶ 批次导出 ──┬─▶ 表内标签(回顾式) ──▶ 立即重训 ──▶ 下一轮
  mutate.py        predict      selection.py     round_NNN_batch.csv
                                                             └─▶ 真实测量(前瞻式) ──▶ PARKED ──▶ --ingest 回填 ──▶ 重训 ──▶ 下一轮
```

目标状态：`init → selected → awaiting_labels → labels_ingested → retrained`；当前检查点主要保存 `init/awaiting_labels/labels_ingested/retrained`，选中批次另有台账（每轮结束写 `state.json`）。
停机判据：还有未回填候选 → `PARKED` + rc 3；候选池耗尽 → `pool_exhausted`；某策略返回空批次 → `empty_batch`。三者都不会写 `DONE`。

每轮产物（`--log-dir`，默认 `runs/<run_id>/checkpoints/`）：

| 文件 | 内容 |
|---|---|
| `ledger.csv` | 候选台账：`run_round, batch_id, candidate_id, sequence, parent_sequence, changed_positions_from_parent, n_from_parent, n_from_wt, source, selection_policy, selection_role, selection_position, model_id, feature_version, protocol_id, pred_gbsa, sigma_gbsa, ood_flag, ood_hamming_threshold, status, measured_gbsa`。**每个预测/OOD/角色字段都按 `selection_position`（可选池内位置）与序列逐行对齐**，批次顺序不再被误当池索引；行追加后不删除，回填吸收/协议钉定只更新状态字段（有审计记录），预测类字段不被改写 |
| `round_NNN_batch.csv` | 该轮交给外部测量的批次（含 `candidate_id`、`pred_gbsa`、`ood_flag`、`protocol_id`），可直接作为回填模板 |
| `round_NNN_batch_manifest.json` | 交接清单：导出列、模型/特征版本、协议、目标、接口版本与运行指纹（同 `fingerprint.json`） |
| `round_NNN_ood_strata.csv` | 按突变数分层的 OOD 报告：池/选中/OOD 计数；回顾式另记逐层 MAE 与层内最优是否被选中 |
| `metrics.csv` | 每轮一行：`n_labeled_before, n_new_unique, n_labeled_after, model_n_train, n_awaiting, requested_budget, effective_budget, pool_available, ood_fraction, batch_ood_fraction, ood_threshold_hamming, ood_train_n_from_wt, status, holdout_spearman_pre, holdout_spearman_post, seconds` |
| `state.json` | 完整状态（已标注序列/值、awaiting、failed、open_batch、历史、溯源），`--resume` 的唯一依据 |
| `fingerprint.json` | 检查点指纹：接口版本、配置、数据 SHA256、候选池/留出/初始标注集哈希、池统计与 `scripts/loop/*.py` 源码哈希；`--resume` 时对配置/数据/池/留出**强制匹配**，源码变动只告警并保留原始指纹 |
| `progress.json` / `history.csv` | 人读摘要 |
| `pending_batches/batches/batch_<id>/{batch.csv, labels.csv, failures.csv, batch_manifest.json}` | ParkOracle 台账；`labels.csv`（pass）与 `failures.csv`（QC fail）只由 `--ingest` 原子写入，fail 持久化、重启后该候选仍被排除 |
| `PARKED` | 停机凭据（含 `batch_id`、待回填条数）；批次闭合（全部 pass/fail）后自动删除 |

**指标时间点**：`model_n_train` 等于**采集前**已标注数，`n_new_unique` 是该轮真正新增的唯一标签数，`holdout_spearman_post` 才是重训后的留出集分数。应分别画出采集前和重训后的曲线，避免把两个时间点混为一步。

## 4. 候选生成 v1（`mutate.py`）

> **必须先知道的事实**：本项目的 2000 条测量库不是“以 WT 为中心的球”，而是**半径约 8–11 的壳**。
> `n_from_wt`（13 个可变位点相对 WT 的差异数）分布为
> `{0:1, 4:2, 5:9, 6:34, 7:80, 8:247, 9:410, 10:481, 11:444, 12:226, 13:66}`，均值 9.87。
> 默认生成 1–3 个突变的候选超出已测突变数范围、4–5 极稀疏（各 2/9 条）；历史按当前二元规则统计的 OOD 比例约 51%，不能表述为“整池 OOD”，也不能仅凭这个比例量化外推误差。
> 因此闭环里的变异范围默认取自已标注集合（`--min-mutations/--max-mutations` 可覆盖），并在日志里打印对比与告警。

- 分层水填充：`stratum_capacity(k) = C(13,k)·3^k`；k=1 时 39 条（恰好是整个 1 突变邻域）；按层轮流分配，避免“全是要 k 个突变”的偏斜；
- 实测范围 4–13 内的总容量 = **67,100,400** 条（`evidence/loop_20260930/candidate_pool_report.json`），远比任何预算大；
- `--candidate-quotas "8:200,10:200,12:100"` 可显式指定层配额；
- 溯源：每条候选记录父序列、`n_from_parent`、`n_from_wt`、`changed_positions_from_parent`、`constraints_version=v1`；
- 去重：生成期排除**完整标准 2000 条表** + 初始标注集 + holdout（`pool_stats.excluded_canonical_table=2000` 记入指纹）；出口期 `_available()` 再排除历史批次全部序列（已测/待测/失败），跨轮跨批次永不重提；
- OOD 分层：`compute_ood`/`ood_threshold` 按实施方案 §4 规则（`n_from_wt` 超出训练范围，或**留一法**最近训练 Hamming 距离超过训练集 LOO 最近邻的 95 分位）打标；**在采集前用当轮训练集计算**，阈值与分层计数记入 `metrics.csv` 与 `round_NNN_ood_strata.csv`（回顾式另记逐层 MAE 与层内最优是否被选中）；
- 生成报告工具：`python tools/candidate_pool_report.py --pool-size 2000 --training-size 400`（只读序列，不读任何标签）。

**C 包实测（seed 1，2000 条，训练集 400 条）**：

| 指标 | 结果 |
|---|---|
| 生成/保留 | 2000 生成 → 1998 保留（2 条与标准表重复，已剔除），`candidate_id` 全部唯一 |
| 分层填充 | 4–13 每层 200 条（水填充按层均分） |
| 与标准表最近距离 | 中位数 4（1–5），说明候选是真新的、不是表内复制 |
| 与训练集最近距离 | 中位数 5（1–6） |
| **OOD 比例** | **0.0**（同范围生成）／对比：默认 1–5 突变生成时为 **0.51** |

也就是：**“候选生成”这一步本身已经可评估、可复现；之前真正的隐患是生成范围与测量范围错位，现已按已标注分布对齐并有告警。**

## 5. 选样策略与当前可用范围

| 策略 | 需要 σ | 语义 |
|---|---|---|
| `random` | 否 | 均匀随机（基线，任何结论都要与它配对比较） |
| `greedy` | 否 | 按 μ 取最优（最小化方向取最小 μ） |
| `greedy_diverse` | 否 | 在 top-`k·budget` 内做 Hamming 贪心多样化 |
| `maxmin_coverage` | 否 | 最大化与已选/已标注集合的最小 Hamming 距离 |
| `mixed_control` | 视配额而定 | 若 uncertainty 桶非零则必须有 σ；无 σ 时需把首桶配额设为 0 |
| `uncertainty_mixed` | 是 | 仅在 σ 可信时启用；无 σ 直接报错并说明原因 |

统一比较条件（写死在同一驱动里）：同预算、同初始标注集、同候选池、同种子序列、只从训练折调参、以真实 GBSA 发现指标为主。

**D 包比较驱动**：`python scripts/loop/strategy_compare.py --seeds 30`（配置 `configs/experiments/loop_strategy_compare_30seed.json`）。
它让每个 seed 下的所有策略共用同一划分、同一候选池、同一预算，并输出：

| 产物 | 内容 |
|---|---|
| `runs.csv` | 每 (seed, 策略, 轮次) 一行：`best_selected`（该策略**自己查询过**的候选里最好的 gbsa）、`pool_best`、`regret`、`best_pred_in_batch`、`holdout_spearman_pre/post`、`ood_fraction` |
| `summary.json` | 每轮均值曲线；相对 `random` 的**配对** Δregret 与 Δholdout-Spearman（bootstrap 95% CI）与胜率 |
| `README.txt` | 本次比较的边界声明与完整命令行 |

发现指标用 `best_selected` 而不是“全部已标注的最优值”：初始标注集是所有策略共用的，算进去会让 regret 变负、掩盖策略差异（这个口径错误在 3-seed 冒烟中被抓到并修正）。
**这些都是代理表上的结论**：标签来自代理表（`TableOracle`），holdout 从不被查询，因此它只回答“哪种策略更快找到代理意义上的强结合序列”，不等于湿实验发现能力；发布级结论需要 100 seeds 与真实前瞻式闭环。

## 6. 怎么跑

```bash
# 1) 回顾式冒烟：验证机器跑通，2 轮
python scripts/run_experiment.py configs/experiments/loop_smoke.json --run-id my_smoke

# 2) 前瞻式：生成新候选 → 导出待测批次 → PARKED
python scripts/run_experiment.py configs/experiments/loop_prospective_park.json --run-id my_park

# 3) 拿到 GBSA 后回填（同一检查点、同一 batch_id、幂等）——推荐走运行器的安全恢复入口：
python scripts/run_experiment.py --resume-run my_park --ingest labels_from_team.csv

# 等价的底层命令（loop.py 会强制核对 checkpoint 指纹）
python scripts/loop/loop.py --mode prospective --resume \
  --log-dir runs/my_park/checkpoints --ingest labels_from_team.csv \
  --output runs/my_park/resume_metrics.csv --candidate-source mutate \
  --rounds 3 --budget 50 --n-init 400 --n-holdout 300 --pool-size 500 \
  --surrogate xgb --oracle park
```

回填 CSV 列（`measurement_status` 只接受 `pass`/`fail`；`pass` 必须有有限 `gbsa`，`fail` 持久化并永久排除该候选；`candidate_id` 会与序列重算比对，`protocol_id` 非空且须在 `--approved-protocols` 白名单内——未钉白名单时只要求非空）：

```
batch_id,candidate_id,sequence,gbsa,measurement_status,protocol_id
<batch_id>,<candidate_id>,<141nt>,<float>,pass,<协议串>
```

交接真实批次（96 条 = 1 板，seed 101）用 `configs/experiments/loop_handoff_96.json`；导出含 `batch_id,candidate_id,sequence,pred_gbsa,ood_flag,protocol_id` 与 `batch_manifest.json`/`fingerprint.json`。**当前协议串是占位符 `gbsa_pending_protocol`：回填前必须与团队确认测量协议，并经审计流程钉定——`python scripts/run_experiment.py --resume-run <run_id> --pin-protocol <协议串>`（写 `protocol_changes.jsonl`，同步重写 config/指纹/台账与两份清单及其内嵌指纹；仅限仍 `PARKED` 且无任何回填的运行，勿手改旧运行配置）。**

服务器上投递用 `python tools/sync_remote.py push <paths>` 与 `run "<cmd>"`；跑之前看 `uptime`，用 `nice -n 19` + `OMP_NUM_THREADS=2`，不打断他人作业。

## 7. 以后要接 MD / 真实 MM-GBSA 需要改什么

**只需要换 Oracle，接口不动。**

1. 已有两条现成路径：`ParkOracle`（批次持久化 + `ingest` 回填，推荐）与 `CommandOracle`（把批次交给外部命令，返回值即标签）；
2. 若 MD 要给不确定度：让代理返回 `sigma`（例如多个 MD 副本的均值/标准差，`uncertainty_kind="md_replica_sd"`），此时才能启用 `uncertainty_mixed`；**不要把副本标准差当模型不确定度写进文档结论**，两者含义不同；
3. 成本控制：未来若有 MD 预算，先明确每轮可测条数与 QC 协议，再固定选样策略；不把未校准 σ 当作概率筛选依据。副本数与噪声水平的研究背景见 [执行方案_MIX复测与MD去噪](执行方案_MIX复测与MD去噪_20260924.md)；
4. 目前**不做**新 MD/MM-GBSA：本阶段只交付可跑通的框架与前瞻式待测批次。

| 回顾式两轮冒烟的 holdout Spearman 上升（0.17→0.32 服务器 / 0.09→0.28 本地） | ⚠️ 仅说明流程可跑 | 读的是表内标签、holdout 与池同源，不能作为选样优于随机的证据 |
| `greedy` 相对 `random` 的 30-seed 表内发现指标 | ✅ 开发尺度证据 | 末轮 regret 0.451 vs 2.130，配对 Δ −1.679，CI [−2.637, −0.785]；仅 15/30 seed 严格胜出，中位差 −0.083。详见 [策略对比_20260930.md](策略对比_20260930.md)。**注意：该 30-seed 包（v1）生成于台账索引修复之前，`pred_gbsa/best_pred_in_batch` 字段不可信；发现指标出自状态标签不受影响，v2 重跑已确认逐位一致（`srv_strategy_compare_30seed_v2_20260930_182900`，`DONE`）** |
| `greedy` 相对 `random` 的 100-seed 预注册确认 | ✅ 已完成 | 主判据达成：配对平均 Δregret −1.878，CI [−2.519, −1.261]；**50 胜/37 平/13 负**、中位差 −0.017，平均优势由改善最大 10 个 seed（−8.41，≈44.8%）驱动，最差 10 个平均 +1.76；Δtop-10% 召回 +0.215（99/100）。判读见 [发布候选预注册_100seed_20260930.md](../项目记录/发布候选预注册_100seed_20260930.md) §5 |
| 数据哈希、脚本清单随运行记录 | ✅ 已验证 | `run_experiment.py` 的 `registry_match`/`source_manifest`；`test_registry_hash_check_and_source_manifest`；缺注册项对正式运行报错（`test_unregistered_dataset_fails_for_formal_runs`） |

额外注意：`batch_id` 由「轮次 + 策略 + 候选 ID 列表」哈希得到，**是内容标识不是运行标识**；同配置不同 run 目录会得到同一个 `batch_id`（本轮观察到的 `dec849101d3e` 即如此），这对“同批次续跑”是好事，但不要用它区分 run。

## 9. 已知尚未完成

- 代理本身的精度/校准未按 30/100-seed 评估（`xgb` 只是可用默认值）；
- 真实前瞻式闭环（F 包）需要真实新测 GBSA 才能成立（96 条批次已 `PARKED`，等真实 QC 协议串与 GBSA 预算，钉定后回填）；
- 历史主动学习脚本（`active_learning_strong/deep`）的符号与标准化缺陷已记录，其“AL≈random”结论不得作为反对选样的证据；修正后的 30/100-seed 比较显示 `greedy` 在平均意义上优于 `random` 但靠少数大幅改善的种子（50 胜/37 平/13 负、中位差≈0），**不能**据此宣称“主动学习大幅有效”。
