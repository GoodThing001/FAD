# 突破方向：0.40 的天花板是标签噪声，不是模型/特征/采样

> **2026-09-30 复核提示：**本文保留 2026-09-23 的研究判断，不再作为当前项目决策。`oracle bound 0.412` 的估计方法未留痕；历史主动学习脚本有优选方向、标准化和特征选择问题，所以“主动学习无效”未经可靠重评估。“GBSA 噪声只能靠 MD 降低”也过于绝对：现有 k-NN Hamming 标签平滑的 100-seed 配对结果有改善，但不能等同于物理真值去噪。当前不新增 MD，直接优化独立 GBSA，先完成候选/选样/回填工程。详见 [总体方案](../项目记录/GBSA代理接口与候选闭环实施方案_20260930.md) §7–9。

> 2026-09-23 调研结论（6 路文献 + 数据验证）。回答「主动学习无效后还有什么办法」。

## 1. 决定性诊断（已亲自验证数据）

**0.40 已是 oracle bound 0.412 的 97%，天花板是标签噪声，不是模型容量、特征或采样。**

从 `fad_proxy2000_v2_full.csv` 直接算出（`scripts/reproduction/label_audit.py` 可复现）：

| 诊断量 | 值 | 含义 |
|---|---|---|
| label 公式 | `0.961*Gap2 + 0.039*gbsa`（精确成立） | 标签 96% 由 NUPACK Gap2 决定 |
| **sp(Gap2, gbsa)** | **0.065** | NUPACK 派生量与真实 MM-GBSA 几乎不相关 |
| sp(gbsa, MFE) | -0.068 | 真实 gbsa 与 NUPACK 折叠能几乎不相关 |
| gbsa 占 label 方差 | 0.73% | MM-GBSA 只占标签 <1% 方差 |
| **gbsa 分布** | std 10.4，max **+109** kcal/mol | 结合能 +109 物理上不可能 → MM-GBSA 未收敛/噪声极大 |
| 当前 best | 0.40（oracle 0.412） | 已到上限的 97% |

**核心含义**：最终标签 `label` 的排名 **96% 由免费的 NUPACK Gap2 决定**（sp(label, Gap2)=0.889），gbsa（代理模型预测的 4% 项）与 Gap2 几乎不相关、且噪声极大。所以：

1. 代理模型（0.40 gbsa Spearman）只是对 4% 项的小修正，其精度对最终标签排名影响很小；
2. 0.40→0.412 的差距是 **gbsa 标签噪声**，主动学习/transformer/新特征都无法越过它（它们改的是模型侧，而瓶颈在标签侧）。

## 2. 突破方向（按"能否抬天花板"分层）

### 第一类：真正抬天花板（唯一实质性突破）

| 动作 | 可行性 | 预期 |
|---|---|---|
| **① 先测标签噪声上限**（副本-副本 Spearman，子集重跑 MM-GBSA ≥2 次） | 高（纯算力） | 一步确认天花板 |
| **② 副本平均去噪 MM-GBSA**（5-15 条短轨迹平均；epsilon_in=4；igb=8 GBn；显式 Mg²⁺+骨架约束+正确缓冲） | 中（需 MD，可分批） | **唯一能推 0.40→0.55-0.65 的路径** |
| **③ 相对 FEP/ΔΔG**（13 位点突变图，近同源序列是 FEP 理想场景，先例：茶碱适配体 Pearson 0.9） | 中（子集） | 金标准标签 |

### 第二类：纯 ML 榨取（只能 +0.01~0.02，越不过 0.41）

- 直接优化秩目标（XGBRanker / LambdaMART / soft-Spearman，而非 MSE）；
- 异方差/逆方差加权（用副本方差当样本权重）。

### 第三类：明确否决（6 路调研一致）

- 3D 结构预测（RhoFold/AF3 对 13 位点单突变低于噪声，且与 MM-GBSA 循环）；
- 几何深度学习、对比学习、迁移学习、100k 池 SSL、数据增广、RNA-FM 嵌入——全部对近同源体系失效；
- 主动学习应重构为「副本/测量预算分配」，而非「新序列选择」。

## 3. 立即第一步：测标签噪声上限

当前无副本级/逐帧 GBSA 数据（服务器与本地均只有单值 gbsa），需从 MD 轨迹重跑。协议：

```bash
# 1. 取子集（如 100 条，覆盖 gbsa 分布 + 突变簇）
python scripts/reproduction/label_audit.py --select-subset 100

# 2. 对子集每条序列跑 ≥2 条独立短轨迹（如 5×20ns），各自算 MM-GBSA
# 3. 计算副本-副本 Spearman（标签噪声上限）
python scripts/reproduction/label_audit.py --replica-file replica_gbsa.csv
```

判读：
- 副本-副本 Spearman ≈ 0.41 → 0.40 已近完美，模型侧彻底到头，转向标签协议审计/重定义目标；
- 副本-副本 Spearman ≈ 0.65 → 副本平均可实打实推 0.40→0.55-0.65，这是唯一真突破。

## 3. dock 不能修正 gbsa（已实测否定）

现有数据有 `dock`（r_i_docking_score，对接分数）。生工团队判断 gbsa（r_psp_MMGBSA_dG_Bind）比 dock 更准确。关键矛盾：gbsa 准但噪（std 10.4，可预测 0.34），dock 净但偏（std 1.05，可预测 0.54），但两者相关仅 **0.289**（本质是两个不同的量）。

实测结论（30-seed，`dock_denoise.py` / `dock_rank_correction.py`；2026-09-24 已修复
目标变换的全数据泄漏为折内变换并重跑，数值微调 ≤0.002，结论不变）：

| 尝试 | 结果 |
|---|---|
| dock 全局融合去噪 gbsa（z-score/秩平均/收缩） | 全部变差（0.21-0.30 vs 基线 0.35；修正版 0.2091/0.2192/0.2093/0.2978 vs 0.3490） |
| 只用低分歧序列评估（诊断 gbsa 噪声是否在分歧处） | 无改善（0.344 vs 0.355；修正版 0.3407 vs 0.3547） |
| dock 排序定向修正 gbsa（高分歧处替换） | 灾难性失败（0.054；修正版 0.0585） |

**结论**：dock 的低方差本质是"它测的是另一个量"（系统偏差），不是"干净"。用它修 gbsa 注入的是偏差，比 gbsa 噪声更糟。**gbsa 的噪声只能靠 MD 副本平均去降**；dock 作为独立目标（0.54）是否采用，是标签公式决策（生工团队定）。

## 4. 一个需要决策的问题：标签公式本身

`label = 0.961*Gap2 + 0.039*gbsa` 是设计决策：它把「结合」目标变成了 96%「未结合折叠稳定性」(MFE)。若目标是「预测结合」，应重新权衡 label 朝 gbsa/Aft 加权（但前提是先给 gbsa 去噪）。这是**一行公式改动 + 一次决策会议**，却是最高杠杆的动作。
