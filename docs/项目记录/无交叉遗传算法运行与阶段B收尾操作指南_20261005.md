# 无交叉遗传算法：运行与阶段 B 收尾操作指南

## 1. 现在可以实践到哪里

搜索层在固定 GBSA 评分器上运行，现支持七种：同起点随机游走、多起点爬山、束搜索、仅变异遗传算法、迭代局部搜索、模拟退火、无交叉AdaLead改编版。遗传算法只有单父本变异，没有交叉。输出为预测候选和谱系，不产生真实 GBSA，也不触发旧 96 条批次回填。代理模型可在此处暂停优化；替换模型时只需满足原预测合同并建立新模型与搜索档案。

总体解释、文献及数据见[生工团队总汇报](../汇报/9月/GBSA优化项目总汇报_生工团队版_20261005.md)。冻结参数和比较设计见[冻结方案](无交叉遗传算法与搜索比较冻结方案_20261005.md)。

## 2. 最短实践：运行一次无交叉遗传算法

本轮已经实际运行过：`local_mutation_only_ga_demo_20261005`，916 次唯一预测、908 条可导出预测候选、8 代后停滞停止、两组；最低预测 6.150741。它只用于工程实践示例，没有真实新标签。完整候选文件在本地 `runs/local_mutation_only_ga_demo_20261005/checkpoints/`。

从项目根目录运行：

```powershell
python scripts/run_experiment.py configs/experiments/search_mutation_only_ga_20261005.json
```

运行器自动创建新的 `runs/<运行编号>/`，保存配置、源代码摘要、环境、数据摘要、输出及完成标记。当前配置用 300 条既有标签训练、16 条共同起点、1024 次唯一预测上限、64 代上限、32 个种群上限、每代 128 个提出槽、2 人锦标赛、2 个精英和 4 代停滞停止。本机没有 XGBoost（极端梯度提升软件库），命令名 `xgb` 实际使用 scikit-learn 的梯度提升回退后端；实际类型与拟合指纹写入模型编号。

不要将本机回退模型与服务器 XGBoost 后端混合汇总；也不要将它当作已发布的五模型排序融合。配置的 300 条训练是为了控制算法比较成本，不等于代理发布评估的训练规模。

## 3. 先查看哪些文件

| 文件 | 读法 |
| --- | --- |
| `checkpoints/fitted_surrogate.pkl` | 保存本次实际拟合的模型权重与模型编号；只有档案身份校验成功后才写入，拒绝续跑不会覆盖旧权重 |
| `metrics.csv` | 一次运行的预测数量、最小预测、停止原因、候选数与组数 |
| `checkpoints/search_candidates.csv` | 全部可导出候选按预测 GBSA 从低到高排序；包含完整序列与单亲谱系 |
| `checkpoints/search_groups.json` | 一组或两组、各组代表与成员；不是两种真实最优结合构象 |
| `checkpoints/search_evaluated.jsonl` | 每条实际评分记录；包含被淘汰子代和已测初始父本 |
| `checkpoints/search_generations.csv` | 代际进度、提出/评分计数、记录的最好可导出预测 |
| `checkpoints/search_snapshot.json` | 模型、数据、训练序列与标签、约束和算法配置指纹 |
| `checkpoints/search_state.json` | 当前种群、随机数状态、已提交日志边界，用于恢复 |
| `checkpoints/files.sha256` | 搜索产物的内容摘要 |

JSON 指 JavaScript 对象表示法；JSONL 为每行一个 JSON 对象；CSV 为逗号分隔值表格；SHA256 为 256 位安全散列算法指纹。文件名称中的英文仅是程序字段标识。

## 4. 改什么、怎样改

复制实验配置另起文件名和运行编号，再改 `arguments`（参数字典）。本轮正式比较已经冻结，实践修改产生新实验，不能写回确认包。

| 参数 | 中文含义 | 修改时的影响 |
| --- | --- | --- |
| `population-size` | 种群上限 | 每代保留的父本数；初始化仍由共同起点数决定 |
| `offspring-size` | 每代提出槽 | 过滤后实际评分量可以更少；影响预测调用批次与耗时 |
| `tournament-size` | 锦标赛人数 | 1 为随机选父本；更大增加偏好低预测父本的压力 |
| `elite-count` | 精英保留数 | 必须至少 1 且不超过种群上限 |
| `one-hop-fraction` | 局部变异选一位点的概率 | 剩余概率为两位点；不引入交叉 |
| `restart-fraction` | 全局重启提出槽比例 | 重启没有局部父本；与局部变异比例分开计算 |
| `max-stagnant-generations` | 连续没有更低可导出预测的停止代数 | 早停后不会自动补足预测上限 |
| `max-unique-predictions` | 首次唯一序列预测上限 | 包括初始父本；重复缓存不另计 |
| `model-seed` | 模型训练随机种子 | 改变模型，必须另起搜索档案；不能复用旧缓存 |
| `seed` | 数据划分与搜索随机种子 | 不等于新 GBSA 测量次数 |

直接脚本路径为 [search_run.py](../../scripts/loop/search_run.py)。正式实验仍建议通过统一运行器启动。搜索按原上下文重新调用可恢复已保存代际边界；运行器不覆盖已有 `run-id`，恢复搜索应保持原 `--log-dir`、数据与参数，且不要手工改指纹。

## 5. 四算法比较与审计

**已有结果直接审计，不必重新训练：**

```powershell
python tools/verify_search_suite.py runs/search_suite_development_20261005
python tools/verify_search_suite.py runs/search_suite_confirmation_20261005
```

**需要从当前代码重新计算时，先另建输出目录。**两份原冻结配置的 `out-dir` 已占用，运行器新编号还会改变套件的输出路径；直接对占用目录启动会被指纹校验拒绝。以下示例新建一份确认配置，原始证据保留：

```powershell
$practiceConfig = Get-Content configs/experiments/search_suite_confirmation_100seed_20261005.json -Raw -Encoding UTF8 | ConvertFrom-Json
$practiceConfig.name = "search_suite_confirmation_practice"
$practiceConfig.arguments.'out-dir' = "runs/search_suite_confirmation_practice"
$practiceJson = $practiceConfig | ConvertTo-Json -Depth 12
$practicePath = Join-Path (Get-Location).Path "configs/experiments/search_suite_confirmation_practice.json"
[System.IO.File]::WriteAllText($practicePath, $practiceJson, [System.Text.UTF8Encoding]::new($false))
python scripts/run_experiment.py configs/experiments/search_suite_confirmation_practice.json
python tools/verify_search_suite.py runs/search_suite_confirmation_practice
```

上面用UTF-8且不带字节顺序标记写配置，以兼容当前运行器；Windows旧版PowerShell的默认UTF-8写法可能带文件头标记，应照例保存。

如果 `search_suite_confirmation_practice` 目录也已有结果，应换新的名称。开发配置同理；当前代码复算是新的核对运行，不能强行恢复修补前的开发档案。默认独立GA配置没有固定占用的套件 `out-dir`，运行器每次新建包，适合先练习。

完整套件会生成 `runs.csv`（每子运行）、`aligned.csv`（实际共同预测次数截面）、`stability.csv`（重新训练与跨代理稳定性）、`ablations.csv`（有限消融）、`fits.csv`（训练耗时和留出集诊断）、`summary.json`（汇总）、`completeness.json`（计划完成核对）、`artifact_audit.json`（逐产物审计）。两进程并行，每次单模型训练和预测均限制线程；本机资源检查见 `runs/search_resources_20261005.json`。

开发套件输出目录固定，用于其内部续跑；再做不同参数应另改 `out-dir`，不能让新配置使用旧结果。套件恢复时先核对源代码与配置指纹，单搜索按已有检查点恢复。新的运行器包装包不应冒充原运行包。

差值一律“算法减随机游走”，负值代表预测更低。配对区间是重复数据划分的计算统计，真实最低 GBSA 和湿实验亲和力没有因此得到证明。两个代理之间不直接比较原始极小预测值，以免混淆不同评分地形。

