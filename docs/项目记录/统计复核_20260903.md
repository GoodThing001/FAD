## B. 重算方法要点

- bootstrap seed：**20260903**；每次 20000 次重采样，`rng.choice(n, n, replace=True)`，CI 取 2.5/97.5 分位。
- Spearman：`scipy.stats.rankdata` + `pearsonr`（Windows 安全实现）。
- 配对 Δ：先按 seed 对齐（候选 − 基线/对照），再对 30/100 个差值做 bootstrap。
- 脚本：`scripts/tools/recalc_evidence_audit.py`；完整结果：`evidence/_recalc_audit_results.json`。
- 关键片段：
```python
def spearman(a, b):
    return float(pearsonr(rankdata(np.asarray(a, float)), rankdata(np.asarray(b, float))).statistic)

def paired_stats(d):
    rng = np.random.default_rng(20260903); m = np.empty(20000)
    for i in range(20000):
        m[i] = d[rng.choice(len(d), len(d), replace=True)].mean()
    return float(d.mean()), float(np.quantile(m, 0.025)), float(np.quantile(m, 0.975)), \
           int((d > 0).sum()), int((d == 0).sum())
```

## C. 数据文件本身的问题

1. **phase1_v8 含 2160 行完全重复**：72 个 `mutation_only × full_52d`（目标×损失×模型）组合，每个 seed 被写入两遍、数值完全相同；去重后为 17280 行 = 576 配置 × 30 seeds。行数声明 19440「相符」但含重复，聚合均值不受影响。
2. **phase1_v8 的 XGB 在 mse/mae/huber_1/huber_2 四种损失下 gbsa_Sp 完全相同**（max 差 = 0.0）：损失维度对 XGB 没有产生任何区分，疑为重复记录或损失未生效，引用「XGB+MAE」等结论时需注意。
3. **phase1_v8 无超参列**（如 n_estimators），「GBR(500) + nested_100 → 0.395」的模型归属无法从 CSV 核对；0.395 只能以「per-seed best over {GBR,XGB}×{mae,huber}@nested_100d = 0.3944±0.0398」口径复现。
4. **30-seed 文件是 100-seed 文件的精确子集，但统计量差异大**（等权融合 0.3904 vs 0.3748）：seeds 1–30 是利好子集。任何文档引用 30-seed 均值时必须注明，不能用 30-seed 数代替 100-seed 发布值。
5. **cluster split 逐 fold 存在 >0.01 的下降**：mutual_info\|GBR 某 fold −0.0112、tree_importance\|GBR −0.0166、spearman\|XGB −0.0250。通过准则（`cluster_split_check.py`：mean_delta ≥ −0.01）下 9/9 通过、summary「all_pass=true」属实；但若按「任何 fold 不比对照下降超过 0.01」的强读法，3/9 格不满足。该检查只有 5 个 fold，且 summary 已注明聚类外推压力弱（仅 8 对成簇）。
6. **「mutation-only + RF 100 seeds 0.365±0.042」的源 CSV 不在 evidence 目录**：无法直接核对；最接近的 phase1 30-seed 切片为 0.3652±0.0439（巧合级接近，但不是同一运行）。v8_fusion 100-seed 的 single RF（303d 配置）= 0.3520，与 0.365 基线是不同配置，勿混用。
7. 其余文件无问题：v8 fusion 两个文件 seeds 完整、无重复；v10/v10b/v11/v12/v13 行数与 seed 1–30 完整；metrics.csv / cluster_split_check.csv 无重复行；数据 CSV 无缺失。
