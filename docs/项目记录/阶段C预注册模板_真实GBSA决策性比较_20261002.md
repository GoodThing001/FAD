## 2. 主终点与判据（先写死）

- **主终点**：每个独立配对单位内，相同真实测量预算下各策略新序列的**最低实测 `gbsa`**（越低越强）。QC 失败、撞车与补位规则先冻结。
- **主判据**：先指定一个主要比较（`<待定：爬山或束>` 对随机游走）及所需独立配对单位数、检验/CI、显著性水平、多重比较处理和停机规则。每个独立单位给出三组最优实测 GBSA，跨单位才可对配对差做 bootstrap CI。**单个 96 条批次即使每组 32 条，也只有一个配对单位，不能给出有意义的跨批 CI 或宣布策略优胜。**
- 若预算只够一批，报告各组的描述性最优值、命中数与 QC 失败率，作为可行性试验；待独立批次/起点累计达到预注册数后再做判定。
- 当前闭环只验收了**单策略搜索档案 → 一/二候选组 → 一批待测**；三策略跨档案组装、撞车去重与补位驱动仍须在真实预算确定后实现、测试并冻结，不能直接拿单策略 PARKED 冒烟充作三臂比较。
- **必须同时报告**（不作为判据但不得省略）：差值中位数/Q25/Q75、胜/平/负、最差 10% 与改善最大 10%、逐批曲线、失败率、按 `n_from_wt` 分层的 OOD 与误差、组内/组间最优、预测—实测排序（Spearman）。
- **判读纪律**：CI 上界 <0 但中位差≈0 或胜率≈50% 时，如实描述为均值/尾部驱动；负结果照写；不把「代理预测更低」当作实测证据。

## 3. 报告与文档要求

1. 真实 GBSA 是本次计算优化任务的验证量；**不把 GBSA 表述为已验证的亲和力或湿实验成功率**。
2. 批次效应、失败样本、重复计算误差全部保留并报告；协议变更走 `protocol_changes.jsonl` 审计。
3. 批次导出/回填沿用现行闭环工程流程（`--resume-run … --pin-protocol`、`--ingest`、PARKED→回填→重训→DONE），每批运行包经 `tools/verify_loop_run.py` 复核。
4. 结论分层：阶段 C 证明的是「该策略在真实 GBSA 上的发现效率」；对更高层的结论（亲和力、体内活性）不作推断。

## 4. 停止/回退门槛（预先写明）

- 若主判据未达成，保留三组原始结果并报告不确定性；下一步先检查代理排序与标签质量，再决定是否扩大预算或变更算法。
- 若预测—实测排序相关性低（与阶段 B 的跨模型 Spearman 0.18–0.30 同量级或更差）→ 优先改善代理与标注，暂停扩大测量投入。
- 若低实测值集中在 OOD/稀疏层且误差分层明显 → 缩小搜索域或降低代数。
